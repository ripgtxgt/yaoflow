# 产品目录、权益表、统一结账与全部服务（10-22，进度表 55–58）

两份「一处登记」：卖什么在 `lib/catalog.ts`，谁能用什么在 `lib/entitlements.ts`。都是服务端文件（会碰到数据库），客户端组件通过页面或接口拿，不直接 import。

## 产品目录 `lib/catalog.ts`

每个产品一行（`CATALOG[id]`）：

| 栏 | 意思 |
|---|---|
| `id` | deep／one／month／year／pass_1／pass_7／pass_30／pack_l／pack_s／qian_personal／qian_card／tarot／bazi_deep／ziwei_deep／astro_deep／hepan／nianshu |
| `kind` | oneoff（一次性）／subscription（订阅）／pass（通卡，带 `days`）／included（只随会员或通卡附带，不单卖） |
| `feature` | 它背后的功能开关（没有＝一直开） |
| `tier` | 记在 `orders.tier` 的名字；订阅计划不记订单行 |
| `path` | 买或用的入口（不带语言） |
| `name(locale)` | Stripe 账单行名称，九种语言，一律「数字内容」措辞 |
| `label[locale]` | 页面与后台用的短名 |
| `price(currency, {first, early, member})` | 各币种价格（minor units）；首次／早鸟／会员价是同一行的变体；`null`＝不单卖 |
| `member` | 会员：included（已含）／discount（8 折）／full（原价） |
| `pass` | 通卡期内可用 |
| `guarantee` | 首次付费保证（24 小时一键退款）适用——只有 deep／one |
| `recover` | 挽回 7 折适用 |
| `retiredBy: "tongka"` | 通卡模式开了以后不再卖给新买家（deep／one／增购包），老用户已买的不动 |
| `group` | 周报与后台的分组：reading／membership／pass／qian／tarot／mingli |

价格的**数字**仍在 `lib/money.ts`（每张表旁边写着它的来历：含税 v3、各市场价位），目录只说这些数字是「什么的价」。`test/catalog.test.ts` 把每个（产品 × 币种 × 变体）锁在 `test/catalog-prices.json`；改价是三步：改 money.ts 的表 → `CATALOG_SNAPSHOT=write npx vitest run test/catalog.test.ts` 重写快照 → 提交两者。

已经从目录读的地方：后台财务页的收款桶（解籤、塔罗、命理不再算进轻解读）、后台各处的档位名（`tierLabelZh`）、统一结账入口（57）、全部服务页（58）。结账接口逐个切到 57 时就都走目录了。

## 会员权益表 `lib/entitlements.ts`

```ts
const r = await rightsFor(customerId);   // 读一次帐号：standing、live row、entitlement、passDays、unlimited
can(r, "chart_report")                    // 表里的答案
const v = useRight(r, "tarot_reading", { ref: token }); // 表＋当天上限（同一个 ref 不重复计）
spendRight(r, "tarot_reading", token);    // 做完事再记一笔
allowance(r, "one")                       // 旧模式的每月额度；通卡模式下 Infinity
followupLimitFor(r, 5)                    // 会员 30，其他 5
```

身份（`standing`）：member（月订／年订 `sub_`）、comp（赠送 `comp_`，所有会员权益、永不计上限）、pass（通卡 `pass_`，1／7／30 天）、card（籤卡）、none。

| 权益 | member | comp | pass | card | 上限（lib/caps.ts） |
|---|---|---|---|---|---|
| deep_reading 六爻深断 | ✓ | ✓ | ✓ | | cast 20 件／天 |
| member_followups 追问上限 30 | ✓ | ✓ | ✓ | | followup 40／天 |
| tarot_reading 塔罗解读 | ✓ | ✓ | ✓ | | tarot 10／天 |

上限只对通卡模式开着时的 member／pass 生效（`capped`），comp 永不计。改权益＝改这张表；加一个权益＝加一行加一个名字。

已切过去的地方（行为不变，`test/entitlements.test.ts` 4 条锁住）：塔罗结账、解籤结账、三个报告接口（含月更的会员判断）、追问（上限与每日 40）、命盘问答、合盘／年书结账的会员 8 折、通卡结账的「已是会员」。还没切的：`/api/me`（整个 entitlement 要给页面）、今日一籤 `accessOf`（它本来就只有一处）、会员每日信的资格（同步函数）、帐号页（显示用）。

## 统一结账 `POST /api/checkout/v2`（57）

```
POST /api/checkout/v2 { product: <目录 id>, locale, currency, timeZone, tzOffsetMinutes, …产品自己的字段 }
  pass_1 / pass_7 / pass_30 → {returnTo?, c?, bs?, remind?}     tarot → {token}     qian_personal → {token}
  qian_card → {}        hepan → {a, b | invite, question?}       nianshu → {input, gender, year, question?}
  month / year → {noMp?, c?, bs?, remind?}                       pack_l / pack_s → {expect?}
```

- 公共部分只写一次：`lib/checkout-core.ts`——币种、路由（Managed Payments 开不开、台港走自家页、大陆路线 alipay＋card）、每张 session 都带的 metadata（locale、currency、country、mp_reason、c、bs、dv、remind）、一次性 session 的建立、失败记一笔。路由规则现在所有产品一致：大陆时钟、简体页 UTC+8 无时区名、人民币金额都不走 Managed Payments（10-22 前塔罗／解籤／合盘／年书四条少了中间那一项）。
- 每个产品一个处理器：`lib/checkout/{pass,tarot,qian,card,hepan,nianshu,sub,pack}.ts`，只写自己的事：目录取价（首次／早鸟／会员变体）、权益表判会员免付、回哪一页、自己的 metadata。
- **旧接口是薄壳**：`/api/pass/checkout`、`/api/tarot/checkout`、`/api/qian/checkout`、`/api/today-qian/card`、`/api/pack/checkout`、`/api/sub/checkout`、`/api/hepan/checkout`、`/api/nianshu/checkout` 各自把 body 交给同一个处理器——前台一个产品一个地切到 v2，行为不变。起卦页自己的 `/api/checkout`（深断／轻解读／带卦买通卡、钱包、赠送）没有并进来：它带着卦面，单买又已停售，留它原样。
- 开关 `checkout-v2`（预览）：只有后台浏览器打得到 v2，其他人照旧走旧接口；两边跑的是同一套处理器，对账一周一致后开放，前台再切。
- 测试 `test/checkout-core.test.ts`（路由规则、公共 metadata、能卖的产品都有价）。

## 全部服务页与主推（58）

- `lib/services.ts`：站上每一项服务一行（免费的擲筊求籤、黃曆、擇日、每日運勢、三个排盘，和目录里的付费项），带页面、开关、有哪些语言、短名与一句话、卡上要标的价（目录 id）、谁已含。只有中文的服务写繁体、简体页转换；六爻、会员、通卡三项九语齐全。
- `/[locale]/services`（开关 `services`，预览）：按「問事／看自己／每天／會員與通卡」分组列出这个语言里有的服务，价格由浏览器里的币种决定（`ServicePrice`：页面把所有币种交给它，它挑一个），年书早鸟期显示原价划掉、会员价另列。非中文页只剩六爻、会员、通卡。
- 「也可以試試」主推：`lib/promo.ts`，`site_settings` 表里每个版面（首页、解籤页、解读页）一组服务 id（最多两个），后台 /admin/features 下方勾选即改、不用部署；没设过用默认（首页与解读页：八字＋塔罗；解籤页：今日一籤＋擲筊）。`PromoStrip` 只显示对这个访客开着的服务，页面自己的服务不推自己；整个条也跟着 `services` 开关走。
